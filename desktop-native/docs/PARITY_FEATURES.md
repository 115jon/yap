## 1. Gateway (`/api/gateway`, MeetingRoom DO)

Opcode enum: `packages/protocol/src/opcodes.ts:15-135`. Client payload
schemas: `packages/protocol/src/client-payloads.ts:40-224`. Server-side
decoding the client does: `packages/protocol/src/server-payloads.ts:46-73`.
Client store: `src/stores/chat-gateway.ts`.

### 1.1 Session lifecycle

- **Identify (op 0)** from the chat store is just
  `{name:"ChatClient", platform, supports_voice_state_deltas:true}`
  (`src/stores/chat-gateway.ts:919-930`). `platform` is `desktop|mobile|web`
  (`src/lib/presence-platform.ts`); it drives the platform icons in presence.
  YapNative should send `"desktop"`.
- **Ready (op 2)**: the chat store reads only `participant_id` and keeps it
  as the resume session id (`server-payloads.ts:54-56`,
  `chat-gateway.ts:932-936`).
- **After Ready** (`chat-gateway.ts:932-978`):
  1. If the user's stored status is not `online`, send PresenceUpdate (op 26)
     `{status}` (`:940-946`).
  2. ServerSubscribe (op 35) `{server_id}` for every server (`:949-952`,
     `:1147-1154`).
  3. ChannelSubscribe (op 27) for the active channel (`:954-957`). Only
     **one** channel is subscribed at a time; switching sends op 28 for the
     old one first (`:1121-1136`).
  4. On a reconnect (not the first Ready): mark message caches stale, rerun
     `bootstrapChat({deferNonCritical:true})` and reload the active channel's
     messages, with reconnect sounds suppressed (`:959-975`).
- **Resume (op 7)** `{session_id, seq_ack}` (`client-payloads.ts:60-63`):
  - Sent on Hello instead of Identify when there is a session id and the
    socket has been Ready before (`chat-gateway.ts:981-992`).
  - `seq_ack` = max `seq` seen on **any** frame (`:163-168`).
  - Success = **Resumed (op 9)**, handled exactly like Ready, so the full
    REST reconcile still runs (`:1002-1004`).
  - Error 4006 SessionInvalid while resuming: clear the session, Identify
    again (`:1007-1014`). 4008 AdmissionRejected: clear the session and stop
    (`:1015-1020`).
  - Server side (`realtime/meeting-room.ts:3133-3200`):
    - resumable for **120 s** after disconnect (`:308`);
    - replay buffer of 100 entries / 256 KB per session (`:317,370`);
    - more than 32 persisted writes while away drops the session, so the
      client falls back to Identify plus REST (`:318`, `:3866-3878`);
    - `seq_ack` must be ≥ the first retained seq − 1, otherwise 4006;
    - a resume from another subject gets 4008 and a close.
- **Heartbeat**: raw `{"op":3}` every `heartbeat_interval` (default 45 s,
  `server-payloads.ts:23`). ACK is op 6.
- **Error (op 18)** `{code, message}`. Codes: `opcodes.ts:162-189`.
- **Reconnect policy**: tickets, backoff, wake-on-visibility, and the slow
  auth-failure retry live in `RealtimeSocket` (`chat-gateway.ts:123-182`,
  `src/lib/realtime-socket/`). A refused ticket (401) shows "Signed out" and
  retries slowly (`:150-153`).
