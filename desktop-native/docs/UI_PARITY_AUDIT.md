# UI parity audit: native client vs web

Pass of 2026-11-06. Both sides ran as the test account "Native Spike" in
"Native Spike Lab" and its DM with Spike Peer, at 1280 x 800, light theme
(the account's synced theme on the web, `YAP_THEME=light` on native).

- Web captures come from `F:/ct/yapn/tools/web-shot.mjs`, which now takes
  `--path`, `--viewport`, `--secrets <file>` and repeatable `--do` steps.
- Native captures come from `shot.ps1`. It now crops to the DWM frame, so
  its pixels match `click.ps1`.
- Pairs are in `F:/ct/yapn/run/parity/<screen>-{web,native}.png`, and the
  fixed state is in `<screen>-native-after.png`.

Web paths are under `src/components/` unless they say otherwise. Native
paths are under `desktop-native/rust/` (the `cpp/` row is under
`desktop-native/`). Line numbers are the state after the fixes.

After the fixes, the vertical rhythm of the channel view matches the web
within 1 px: header to body, the gap between groups, follow-ups, and the
mention row (`server-channel-*`).

## Totals

- 48 differences found.
- 39 fixed:
  - shell: 18;
  - home: 3;
  - popovers and menus: 7;
  - panels, settings, shop, embeds, dialogs and toasts: 11.
- 6 kept on purpose: native is better, a native extra, or the native title bar.
- 2 not fixed: DM calls and mutual servers. Both need features native does not have yet.
- 1 not verified (voice) and 1 that is a data difference only (Ctrl+K).
