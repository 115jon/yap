# YapNative UI parity spec

This spec covers how the QML client in `desktop-native/` can match the shipped Yap desktop app, which is the React UI inside the Tauri+CEF shell, and then improve on it. The source of truth is `DESIGN.md` (Talk Tree, with the "C · Poster" layer on top) and `src/styles/tokens.css`. Where the code and DESIGN.md disagree, this spec follows the code and flags the conflict.

All paths are relative to the repo root. `file:N` means a line number. **UNVERIFIED** marks a guess or something not checked against a running build.

Visual references:

- The dev-only `/ui-fixtures?surface=<id>&theme=<theme>` route (`src/routes/ui-fixtures.tsx:7-20`) renders every surface with mocked data. The dispatch is in `src/components/dev/UiFixtures.tsx`.
- The full surface matrix is in `C:\Users\jon\.cache\ralph-shots\jobs.json`: 289 frames, six themes, 1440x900 and 1280x720. Its capture harness is `capture.mjs` in the same folder. No capture PNGs of the fixture matrix were kept on disk.
- Stills that do exist: `F:\ct\brand\yap\shots\yap-02-chat.png`, `yap-04-chat-dark.png`, `yap-06-coldload.png`, `yap-08-desktop.png` and `yap-26-signin-frames.png`; themed marks in `F:\ct\brand\yap\themed\*.png`; marketing screenshots in `public/screenshots/home/{chat,tree,voice,share,share-stage,soundboard,listen}-{dark,light}.webp`; and `C:\Users\jon\.cache\ralph-shots\perf\desktop-prod\signin-{a,b,c}.png`.

Priority levels:

- **P0**: needed for daily use (sign in, chat, voice, the basics of DMs).
- **P1**: expected within weeks.
- **P2**: long tail. These can be hosted in WebView2 first (FEASIBILITY.md §4).

Fixture ids are given in `code` so each surface can be compared side by side.

## 3. Tokens → `Theme.qml` singleton

### 3.1 Structure

There are three layers, the same as `tokens.css:1-18`:

1. **Inputs.** A JS object per theme id holding the literal hexes and mix percentages from `tokens.css` lines 21-275.
2. **Roles.** Readonly properties derived from the inputs. `color-mix(in srgb, X p%, transparent)` is exactly `Qt.rgba(X.r, X.g, X.b, p/100)`, so every tint, line and halo is an alpha of ink or of an LED.
3. **No legacy aliases.**

```qml
pragma Singleton
QtObject {
  property string themeId: "dark"            // dark|light|miku-dark|miku-light|spiderman-dark|spiderman-light
  readonly property var t: Themes.inputs[themeId]

  function a(c, p) { return Qt.rgba(c.r, c.g, c.b, p) }
  readonly property color ply0: t.ply0 /* … ply4, ink1..3, inkOff */
  readonly property color tint1: a(ink1, .06); readonly property color tint2: a(ink1, .10); readonly property color tint3: a(ink1, .16)
```

### 3.4 Fonts: how to ship them

- **What is installed.** The web loads Fontsource variable WOFF2 (`src/styles.css:9-12`).
  - Qt cannot read WOFF2.
  - The resonance static Qt is **6.6.3** (FEASIBILITY.md:89). Per-font variable-axis control (`QFont::setVariableAxis`) arrived in Qt 6.7 (UNVERIFIED against this build), so `wdth` and `opsz` cannot be set at runtime. Cut static instances.
- **Proven pipeline in the repo.** `desktop/scripts/build-installer-fonts.py:1-90` already cuts static TTFs from the Fontsource `*-standard-normal.woff2` files. Those files carry wght, opsz and wdth. The script uses fontTools `instantiateVariableFont`, renames each cut to its own family, and subsets it. Its output is `desktop/installer/Assets/Fonts/{Display-ExtraBold,Display-SemiBold,Geist-Regular,Geist-Medium,Silk-Condensed,Silk-Wide,Num-Medium}.ttf`. For QML, fork it as `desktop-native/scripts/build-fonts.py` with two changes:
  - **Do not bake tracking** (the `track()` step at `:56-64`). Qt has `letterSpacing`, and baked advances would double it.
  - Add the cuts the app needs:
    - Bricolage 600@opsz15, 700@opsz15, 700@opsz20, 800@opsz18, 800@opsz28, 800@opsz40.
    - Geist 400, 500, 600 and 400 italic (`geist-latin-wght-{normal,italic}.woff2`).
    - Martian 500/wdth90, 600/wdth100, 500/wdth100.
    - Geist Mono 400.
  - Keep latin, latin-ext and cyrillic. Load them with `FontLoader` or `QFontDatabase::addApplicationFont` from qrc. Use one family name per opsz/wdth cut, for example `Yap Bricolage Title` and `Yap Martian Silk`, so weight matching never crosses cuts.
- **Alternative static TTFs already on disk.** `node_modules/.pnpm/@expo-google-fonts+{geist,geist-mono,bricolage-grotesque,martian-mono}@*/…/*.ttf` cover weights 100-800. These are the Google Fonts static instances, with Bricolage at its default opsz and Martian at its default width (UNVERIFIED which). They do not give condensed silkscreen or opsz, so use them only as a stopgap.
- **Display-name fonts** for collectibles (P2): `@fontsource/{bungee,permanent-marker,fredoka,cormorant-garamond,cinzel,press-start-2p,unifrakturmaguntia}` (`src/display-name-fonts.css`). Convert them the same way with `font.flavor=None`.
- **Rendering.** Chromium draws with DirectWrite grayscale AA. For matching small text, try `Text.NativeRendering` for 11-15px and `QtRendering` for 18px and up. Compare against fixture captures (UNVERIFIED which looks closer).
- **Licence.** The fonts are OFL. Ship `OFL.txt` as the installer does.

### 3.5 Icons

- **Source.** `@phosphor-icons/core@2.1.1` is in node_modules with SVGs at `assets/{bold,fill,...}/*.svg`, 1512 per weight. The app does not ship all of them. `scripts/generate-phosphor-icons.mjs` reads `src/components/ui/icon/mapping.ts`, which maps about 180 app concepts to glyphs, and emits `glyphs.generated.ts`: 169 Bold plus 37 Fill paths on a 256 grid (header, line 3).
- **States.** Idle is Bold, active is Fill, and "off" is the Fill of the concept's off partner. Some concepts draw a Phosphor slash: path `M48 40 208 216`, stroke 24 (Bold) or 16 (Fill), with a 12px clear band cut on each side (`ui/icon/Icon.tsx:12-21,43-48`).
- **Sizes.** xs 12, sm 16, md 18, lg 20, xl 24, 2xl 32, 3xl 48 (`ui/icon/tokens.ts`).
- **No TTF icon font in node_modules.** Phosphor publishes one in `@phosphor-icons/web`, which is not installed. Recommended approach:
  1. **Generate from the same mapping.** Extend `generate-phosphor-icons.mjs` with a `--qml` target that writes `desktop-native/rust/qml/icons/{concept}-{bold,fill,off}.svg`. The slash and mask are pre-composited into plain paths, and the `rotate` from mapping.ts is applied. Also write a `Glyphs.js` map of path strings.
  2. **Render** with a small `Icon.qml` that uses `Shape { preferredRendererType: Shape.CurveRenderer; ShapePath { fillColor: color; PathSvg { path } } }` scaled by `size/256`. Colour then binds like `currentColor`. The prototype already uses Shape plus CurveRenderer (`ChannelSidebar.qml:202-217`).
  3. **For long lists** (member rows, reactions), measure first. If Shape items cost too much, fall back to a TTF icon font built from the same SVGs, for example with fantasticon, so icons become `Text` glyphs in the glyph cache. Avoid `Image` plus `MultiEffect` colorize per icon.
  4. Keep the concept names (`textChannel`, `voiceChannel`, `mic`, `deafen`, `screenShare` and so on). That keeps the QML and React mappings diff-able.
- **Window controls** use `minus`, `windowMaximize`, `windowRestore` and `close` at 12px (`desktop-entry.tsx:252-261`). `public/window-controls/*.svg` also exist.

### 4.3 Tree (the signature)

`ui/tree.tsx:7-31`, `foundation.css:133-260`, DESIGN.md:460-462.

- **Drawing.** Each leaf draws three 1px `guide` segments:
  - up: from the row top to its middle, at x = guideX;
  - tick: 8px wide at mid-row;
  - down: to the bottom, except on the last leaf.
- **Stem.** The first child's up-segment extends by `stem` (8) to reach the channel glyph.
- **Lit path.** A `self` or `current` leaf paints its up and tick segments, and every earlier sibling's trunk, in `path` (accent ink). Its unlit LED node fills in `path`. A lit talk LED paints over it.
- **QML.** Make `TreeLeaf` a delegate with three `Rectangle`s bound to `index`, `count` and `pathIndex`, so nothing is measured. Compute `pathIndex` per branch in the model (the index of self). Segments for `i < pathIndex` and the self segment use `Theme.path`.
- **Join.** Only after first paint (`ListView.add` transition): fade plus `y` from -4 over 200ms, and the segments scale from their origin over 160ms with a 40ms delay. Leave: fade out over 140ms (exit), and the row above stops drawing its down segment at once. Nothing animates on the initial model load.
- **Voice occupant row.** 28 high, gap 8, 24px avatar, Geist 13/500 ink-2. The current user and anyone speaking get ink-1. Trailing glyph cluster at 14px, gap 4 (see §1.4). A drag handle appears for members who can move users.

### Where native can beat the web

- **Text.** Real DirectWrite with no CEF layer and less GPU idle cost. Keep the on-demand scene graph honest; a test probe is the native analogue of `idle-probe.mjs`.
- **Speaking LEDs.** Deliver them as a per-row role change from Rust, so one flip is one node update. That is cheaper than the web's attribute path.
- **Window chrome.** A frameless native window can keep Win11 snap layouts, which the web shell emulates with invoke calls (`desktop-entry.tsx:144-171`).
- **Overlays.** Thumbnail toolbar, overlay icon and jump lists can be first-class without the Tauri bridge.
